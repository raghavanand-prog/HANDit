## Notes

- **Origin check.** A browser page on another site can't open a Room through this server: the Worker refuses a request whose `Origin` isn't the site's own (HTTP 403), before the per-IP counters, so a hostile page can't use up a visitor's allowance. Requests without an `Origin` aren't browser pages and get no extra access. Local development lists its extra origin in `ALLOWED_ORIGINS`; production leaves it empty.
- **No logging.** Worker observability is off (`wrangler.jsonc`), nothing in `web/src` or `worker/src` may call `console` (the linter fails the build), and the Room and Limiter store only the minimum for their rules and delete it when they end.
- **Cloudflare's own headers.** Responses served from `workers.dev` also carry Cloudflare's network-error-reporting headers (`report-to`, `nel`). They make a browser report network failures to Cloudflare, not the page itself contacting another origin. A custom domain (a later choice) gives control over them.
- **Left to the owner.** Nothing here removes the "not independently audited" label; that needs an external review.

## Owner steps

### 8 and S11: packet capture (about 15 minutes)

On the Mac, with Wireshark installed (free, wireshark.org) or `tcpdump` and Wireshark to read the file:
1. Open the live site on the Mac and on a phone on the same Wi-Fi.
2. Start a capture on the Wi-Fi interface: `sudo tcpdump -i en0 -w handit.pcap` (stop with Control-C after the transfer).
3. Send a few photos from one device to the other.
4. Open `handit.pcap` in Wireshark. Filter `udp`, then **Statistics → Conversations → UDP**: the large conversation between the two devices' addresses is the data path. Choose **Analyze → Decode As… → DTLS** if it isn't recognised.
5. Check that the payload is DTLS "Application Data" and nothing readable: search the capture for a file name or a word from the photos (**Edit → Find Packet → String**); there must be no match.
6. Record the result in `docs/testing.md` under S11.

### 10: account settings

- **Two-factor authentication.** GitHub: **Settings → Password and authentication**. Cloudflare: **My Profile → Authentication**.
- **Protect `main`.** Repository **Settings → Rules → Rulesets → New branch ruleset**, target the default branch, enable **Require a pull request before merging** and **Require status checks to pass** (add `check`).
- **Deploy token.** The Cloudflare token for CI should only have **Account → Workers Scripts → Edit** for your account. Add it with the account ID as the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` under **Settings → Secrets and variables → Actions**.

### 9: Dependabot and private reporting

- Repository **Settings → Advanced Security** (or **Code security**): turn on **Dependabot alerts** and **Private vulnerability reporting**. `SECURITY.md` points reporters to the second.
